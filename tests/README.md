# Тесты

Не полноценный тест-фреймворк (GUT и т.п. не подключены) — набор отдельных
`extends SceneTree` GDScript-скриптов, каждый поднимает `Main.tscn` и
проверяет конкретное поведение, печатая `RESULT: PASS`/`FAIL` (и код
возврата 0/1). Один файл — одна область: `ball_hit_test.gd` про формулу
удара, `paddle_bounds_test.gd` про clamp/параллакс весла игрока, и т.д.

## Запуск

Один тест:

```bash
"C:/Users/user/Desktop/godot/4.7.1/Godot_v4.7.1-stable_win64_console.exe" --headless --path "C:/Users/user/Documents/galaxy-pong-2" -s "res://tests/ball_hit_test.gd"
```

Все тесты подряд:

```bash
for f in tests/*.gd; do
  "C:/Users/user/Desktop/godot/4.7.1/Godot_v4.7.1-stable_win64_console.exe" --headless --path "C:/Users/user/Documents/galaxy-pong-2" -s "res://$f"
done
```

Путь к Godot зафиксирован в памяти проекта (reference-godot-cli), там же —
известный нюанс с самопроизвольно возникающим `node_3d.tscn` в корне
проекта после headless-запусков (безвредно, просто удалить перед коммитом).

## Что стоит добавлять сюда

Новый файл — когда проверяется законченное поведение скрипта/фичи, которое
имеет смысл перепроверять при будущих изменениях (регрессия). Разовые
диагностические скрипты (например, для локализации конкретного бага) можно
не сохранять, если после починки они уже ничего не проверяют, чего не
проверяют существующие файлы.
